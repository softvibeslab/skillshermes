# Video/documentary to viable project brief

Use this when a user shares a YouTube documentary/video and asks to develop an idea, business concept, MVP, or project from it.

## Workflow

1. Fetch transcript with language fallback, e.g. `--language es,en`; if no transcript, retry without language.
2. Extract only the actionable insights relevant to the user's goal; do not summarize every section unless requested.
3. Translate insights into a project brief:
   - core insight from the video
   - problem statement
   - target users / best initial segment
   - product concept and positioning
   - MVP scope
   - explicitly excluded features (YAGNI)
   - 7/14/30-day validation plan
   - success metrics
   - beta offer / pricing hypothesis when business-oriented
   - immediate next actions
4. If the user has a known knowledge base/vault convention, save the project brief in the appropriate project folder.
5. Final reply should be concise: say what was created, where it was saved, the recommended viable direction, and the next step.

## Useful framing

Avoid turning documentary insights into a vague content summary. A good output converts research into decisions: who to serve first, what pain to solve, what not to build yet, how to validate, and what metric proves value.

## Example sections

- Idea base
- Insight from the documentary
- Segment recommended for starting
- MVP of 7–14 days
- Features included / not included
- Pilot metrics
- Offer beta
- Roadmap de 30 días
- Demo flows
- Próximas acciones inmediatas
